> **GARUDA VISION** is an enterprise-grade Digital Twin and Real-Time Telemetry Visualization Platform for Autonomous Ground Vehicles (AGVs). It features a deterministic kinematic vehicle movement model, spatial 32-beam LiDAR raycasting, dynamic obstacle risk assessment (Time-To-Collision), full-duplex WebSocket streaming at 20 Hz, and an aeronautic/cyber-tactical 3D HUD.

---

## ⚠️ Synthetic Data Disclaimer

> **IMPORTANT NOTICE**:  
> All vehicle telemetry, obstacle positions, and LiDAR point clouds generated by the default provider in this platform are **MATHEMATICALLY SYNTHESIZED AND SIMULATED**.  
> They represent deterministic mathematical models (Catmull-Rom spline kinematics, Euler integration, and bounding-box raycasting) and **DO NOT** claim to represent uncalibrated physical sensor measurements.  
> Every payload explicitly includes `header.isSimulated: true` and `header.dataSource: "SYNTHETIC"` (or `"CARLA_BRIDGE"`).

## 🚀 Key Features

### 1. Modular Data-Source Architecture
- **SyntheticDataProvider**: Analytical, deterministic vehicle kinematics, predefined static/dynamic obstacles, 32-beam simulated LiDAR point clouds, and obstacle distance/TTC calculation. Zero arbitrary random numbers.
- **CarlaDataProvider**: Production-ready bridge architecture designed for CARLA Simulator integration via TCP/REST bridge (Town03, Python API), featuring automatic fallback simulation and seamless telemetry normalization to the standardized schema.
- **Data Source Independence**: The frontend dashboard and Three.js 3D viewport consume the standardized telemetry contract independently of which provider is active.

### 2. High-Fidelity 3D Digital Twin (Three.js)
- **Procedural Ego Vehicle (`GARUDA-EGO-01`)**: Detailed aerodynamic chassis, glass cockpit, steering front wheels, rotating alloy wheels, forward spot headlights, and dynamic brake lights that illuminate upon deceleration.
- **Roof-Mounted LiDAR Scanner**: Realistic rotating puck (~600 RPM) with 360° laser sweep holographic fan.
- **Dynamic 3D Obstacles**: Bounding boxes with wireframe edges, translucent fills, and live billboard HUD badges showing ID, distance, relative velocity, TTC, and color-coded risk levels.
- **LiDAR Point Cloud Engine**: Preallocated `THREE.BufferGeometry` with elevation/intensity gradient shader (cyan $\to$ purple $\to$ gold) operating at 60 FPS without garbage-collection stalls.
- **4 Camera Perspectives**:
  - `CHASE`: Smooth third-person following camera behind the vehicle.
  - `TOP_DOWN`: Tactical bird's-eye god view.
  - `COCKPIT`: Driver's first-person perspective looking out through the front windshield.
  - `FREE_ORBIT`: 360° inspection using OrbitControls.

### 3. Cyber-Tactical HUD & Telemetry Dashboard
- **Velocity Dynamics**: Speedometer dial with dual digital readouts (km/h and m/s), gear matrix (`P R N D`), and throttle/brake percentage bars.
- **Kinematic Meters**: Acceleration dial with longitudinal/lateral split, steering angle indicator (bounded to $\pm 35^\circ$), and digital compass rose with yaw/heading.
- **Spatial Positioning**: Global coordinates $(X, Y, Z)$, odometry distance tracker, and active road sector.
- **Obstacle Threat Matrix**: Real-time table displaying obstacle ID, classification (Vehicle, Pedestrian, Cyclist, Barrier), distance, bearing, relative velocity, TTC, and risk badge.
- **Dynamic Chart.js Analytics**: Rolling 50-sample telemetry graphs for:
  1. Speed (km/h) vs. Time
  2. Acceleration ($\text{m/s}^2$) vs. Time
  3. Steering Angle ($^\circ$) vs. Time
  4. Minimum Proximity & Time-To-Collision (TTC) Trend
- **Edge Diagnostics Matrix**: State of Charge (SoC %), battery pack voltage, inverter motor temperature, CPU load, pipeline latency, and subsystem health monitors.

### 4. Interactive Simulation Control Deck
- **Playback Controls**: Start, Pause, Step-Forward (frame-by-frame inspection), and Reset.
- **Frequency Selector**: 10 Hz, 20 Hz, 30 Hz, and 50 Hz streaming rates.
- **Provider Switcher**: Instant hot-swap between `SYNTHETIC` and `CARLA_BRIDGE`.
- **Sensor Noise Modeling**: Optional toggleable Box-Muller Gaussian sensor jitter.

## 🚦 Quick Start Guide

### Prerequisites
- **Node.js**: v18.0.0 or higher
- **npm**: v9.0.0 or higher

### Installation
```bash
# Clone the repository
git clone https://github.com/your-org/Real-Time-Autonomous-Vehicle-Telemetry-Obstacle-Monitoring-Dashboard.git
cd Real-Time-Autonomous-Vehicle-Telemetry-Obstacle-Monitoring-Dashboard

# Install backend dependencies (express, ws)
npm install
```

### Running the Application
```bash
# Start the telemetry server & dashboard (Default port: 3000)
npm start
```

Open your browser and navigate to:
```
http://localhost:3000
```

To run on a custom port:
```bash
PORT=8080 npm start
```

## 📡 REST & WebSocket API Specification

### REST Endpoints
| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/status` | Returns active provider, running state, rate (Hz), client count, uptime |
| `GET` | `/api/telemetry/latest` | Returns instantaneous snapshot of latest standardized telemetry packet |
| `POST`| `/api/simulation/control` | Dispatches control commands (`START`, `PAUSE`, `RESET`, `STEP`, `SET_PROVIDER`) |
| `GET` | `/api/carla/status` | Returns CARLA Simulator bridge connection status, host, port, and health |
| `GET` | `/api/health` | Lightweight service health probe (`{ "status": "UP" }`) |

### WebSocket Communication Protocol (`ws://localhost:3000/ws`)
- **Telemetry Broadcast (Server $\to$ Client, 20 Hz)**:
  ```json
  {
    "type": "TELEMETRY",
    "data": { ...standardized_telemetry_payload... }
  }
  ```
- **Client Commands (Client $\to$ Server)**:
  - Play/Pause: `{ "type": "SIM_CONTROL", "command": "START" | "PAUSE" | "RESET" | "STEP" }`
  - Update Rate: `{ "type": "SET_RATE", "rateHz": 10 | 20 | 30 | 50 }`
  - Provider Swap: `{ "type": "SET_PROVIDER", "provider": "SYNTHETIC" | "CARLA" }`
  - Noise Toggle: `{ "type": "TOGGLE_NOISE", "enabled": true | false }`

## 🏎️ CARLA Simulator Integration

GARUDA VISION includes a dedicated `CarlaDataProvider` engineered for hardware-in-the-loop (HIL) and software-in-the-loop (SIL) testing with CARLA:

1. **Python Bridge Script**: Connect your CARLA Python script to the backend REST endpoint or WebSocket.
2. **Coordinate Transformation**: Automatically translates CARLA's Unreal Engine Left-Handed frame ($+X$ Forward, $+Y$ Right, $+Z$ Up) into the autonomous vehicle ISO 8855 Right-Handed standard ($+X$ Forward, $+Y$ Left, $+Z$ Up).
3. **Resilient Fallback Mode**: If CARLA disconnects or is not yet running, `CarlaDataProvider` automatically transitions to `FALLBACK_SIMULATION` without disrupting dashboard consumers.
